# Implementation Details: Three-Layer URL Detection

**Deep Dive into how dynamic URL detection works at each layer**

---

## Overview

The solution implements URL detection at **three layers** of the Next.js stack:

1. **Browser Client Layer** - `window.location.origin` detection
2. **Server Client Layer** - Request header detection  
3. **Middleware Layer** - Request header detection for auth

Each layer independently detects the correct URL, creating a robust system that works in any context.

---

## Layer 1: Browser Client

**File:** `frontend/src/lib/supabase/client.ts`

### Implementation

```typescript
import { createBrowserClient } from '@supabase/ssr'

export function createClient() {
  // Dynamically detect the browser's origin at runtime
  const supabaseUrl = typeof window !== 'undefined' 
    ? window.location.origin  // Browser: "https://kortix.syhc.dev"
    : 'http://localhost:3000'  // SSR fallback (shouldn't execute)
  
  return createBrowserClient(
    supabaseUrl,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      isSingleton: true,  // Reuse same instance
    }
  )
}
```

### How It Works

| Context | `window.location.origin` | Requests Go To |
|---------|--------------------------|-----------------|
| `localhost:3000` | `http://localhost:3000` | `http://localhost:3000/auth/v1/*` |
| `kortix.syhc.dev` | `https://kortix.syhc.dev` | `https://kortix.syhc.dev/auth/v1/*` |

### Key Points

- **Called only in browser:** `typeof window !== 'undefined'` check ensures it runs client-side
- **Automatically detects domain:** No hardcoding needed, works on any domain
- **Relative URLs:** Browser requests go to `/auth/v1/*` (same-origin)
- **Singleton pattern:** Same instance reused for efficiency

### Request Flow

```
Browser page loads
    ↓
JavaScript executes: createClient()
    ↓
Detects: window.location.origin = "https://kortix.syhc.dev"
    ↓
Creates Supabase client with URL: "https://kortix.syhc.dev"
    ↓
Browser makes request: POST https://kortix.syhc.dev/auth/v1/token
    ↓
Cloudflare Tunnel intercepts
    ↓
Routes to: http://localhost:3000/auth/v1/token
    ↓
Next.js server-side rewrite kicks in
    ↓
Rewrite destination: http://supabase-kong:8000/auth/v1/token
```

## Layer 2: Server Client

**File:** `frontend/src/lib/supabase/server.ts`

### Implementation

```typescript
'use server'  // Server Component directive
import { createServerClient } from '@supabase/ssr'
import { cookies, headers } from 'next/headers'

export async function createClient() {
  const cookieStore = await cookies()
  const headerStore = await headers()

  // Extract origin information from request headers
  const origin = headerStore.get('x-forwarded-host') || headerStore.get('host')
  const protocol = headerStore.get('x-forwarded-proto') || 'http'
  
  // Build the Supabase URL from headers
  const supabaseUrl = origin 
    ? `${protocol}://${origin}`
    : process.env.NEXT_PUBLIC_SUPABASE_URL!

  return createServerClient(
    supabaseUrl,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll()
        },
        setAll(cookiesToSet) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options)
            )
          } catch (err) {
            // Caught if called from Server Component
            // This is expected behavior
          }
        },
      },
    }
  )
}
```

### Header Detection Logic

| Header | Source | Purpose |
|--------|--------|---------|
| `x-forwarded-host` | Cloudflare Tunnel | The original domain |
| `x-forwarded-proto` | Cloudflare Tunnel | The original protocol (http/https) |
| `host` | Direct request | The domain (fallback) |

### Context Examples

#### **Localhost (Direct)**
```
Request Headers:
  host: localhost:3000
  x-forwarded-host: undefined
  x-forwarded-proto: undefined

Detection:
  origin = "localhost:3000"
  protocol = "http"
  supabaseUrl = "http://localhost:3000"
```

#### **Cloudflare Tunnel**
```
Request Headers:
  host: localhost:3000  (internal)
  x-forwarded-host: kortix.syhc.dev  (original)
  x-forwarded-proto: https  (original protocol)

Detection:
  origin = "kortix.syhc.dev"
  protocol = "https"
  supabaseUrl = "https://kortix.syhc.dev"
```

### Request Flow

```
User accesses page via Cloudflare
    ↓
Cloudflare Tunnel routes to: localhost:3000 (internal)
    ↓
But adds headers:
  x-forwarded-host: kortix.syhc.dev
  x-forwarded-proto: https
    ↓
Server Component calls: createClient()
    ↓
Reads headers: origin = "kortix.syhc.dev", protocol = "https"
    ↓
Creates client with: supabaseUrl = "https://kortix.syhc.dev"
    ↓
Server-side data fetching uses correct URL
```

### Why x-forwarded-* Headers?

**HTTP Standard:** When a request passes through a proxy (like Cloudflare), the proxy should preserve the original request information:
- `x-forwarded-for`: Original client IP
- `x-forwarded-host`: Original host
- `x-forwarded-proto`: Original protocol (http/https)

**Why it matters:** Server needs to know the **original request** came from `https://kortix.syhc.dev`, not the internal `localhost:3000`.

## Layer 3: Middleware

**File:** `frontend/src/middleware.ts`

### Implementation

```typescript
import { NextRequest, NextResponse } from 'next/server'
import { createServerClient } from '@supabase/ssr'

export async function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl
  
  // Skip authentication for public routes
  if (PUBLIC_ROUTES.includes(pathname)) {
    return NextResponse.next()
  }

  // For protected routes, extract origin from request
  const host = request.headers.get('host') || 'localhost:3000'
  const protocol = request.headers.get('x-forwarded-proto') || 'http'
  const supabaseUrl = `${protocol}://${host}`

  // Create Supabase client with detected URL
  const supabase = createServerClient(
    supabaseUrl,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll()
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) => 
            request.cookies.set(name, value)
          )
        },
      },
    }
  )

  // Check authentication with detected URL
  const { data: { user }, error } = await supabase.auth.getUser()

  if (error || !user) {
    // User not authenticated - redirect to auth page
    const url = request.nextUrl.clone()
    url.pathname = '/auth'
    url.searchParams.set('redirect', pathname)
    return NextResponse.redirect(url)
  }

  // User authenticated - continue
  return NextResponse.next({
    request,
  })
}

export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
}
```

### Middleware Execution

```
Incoming request to protected route
    ↓
Middleware runs BEFORE Server Components
    ↓
Extract: host = "kortix.syhc.dev", protocol = "https"
    ↓
Create Supabase client with: supabaseUrl = "https://kortix.syhc.dev"
    ↓
Check: await supabase.auth.getUser()
    ↓
If authenticated: Allow request to continue
If not authenticated: Redirect to /auth page
```

### Why Middleware?

| Purpose | Why Middleware |
|---------|-----------------|
| Global auth checks | Runs for EVERY route automatically |
| Access to request info | Has full access to headers |
| Early termination | Can redirect before rendering |
| Cookie management | Can read/write cookies before Server Component |

### Route Protection Flow

```
User visits: https://kortix.syhc.dev/dashboard

Middleware intercepts
    ↓
Checks if user authenticated (with correct URL)
    ↓
Not authenticated?
  ↓ Redirect to /auth
    ↓
Authenticated?
  ↓ Continue to /dashboard

Server Component renders dashboard
```

## Error Handling

### What If Headers Are Missing?

```typescript
// Server Client fallback
const origin = headerStore.get('x-forwarded-host') || headerStore.get('host')
const supabaseUrl = origin 
  ? `${protocol}://${origin}`
  : process.env.NEXT_PUBLIC_SUPABASE_URL!  // ← Fallback
```

- **If headers present:** Uses dynamic URL
- **If headers missing:** Falls back to build-time env var
- **Safety:** Always has a value to use

### What If Browser Client Fails?

```typescript
const supabaseUrl = typeof window !== 'undefined' 
  ? window.location.origin
  : 'http://localhost:3000'  // ← Fallback
```

- **SSR/Server contexts:** Falls back to localhost
- **Browser contexts:** Uses actual origin
- **Safety:** Browser client never actually uses this (only Server Components execute SSR)

## Performance Implications

### Cache Strategy

- **Build-time rewrites:** Compiled once, very fast
- **Runtime detection:** Minimal overhead (header reads)
- **Client creation:** Happens once per request
- **Singleton pattern:** Browser client reused across components

### No Performance Issues

| Layer | Cost | Why |
|-------|------|-----|
| Browser Client | 1 header read | Per page load |
| Server Client | 2 header reads | Per Server Component |
| Middleware | 2 header reads | Per request |
| Build-time rewrites | 0 runtime cost | Compiled into routes |
