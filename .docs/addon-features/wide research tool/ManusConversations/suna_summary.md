# Suna Repository Analysis

This document provides a comprehensive summary of the technical architecture and folder structure of the `kortix-ai/suna` GitHub repository.

## 1. Overall Architecture

The Suna platform is a comprehensive open-source solution for building, managing, and training AI agents. Its architecture is designed in a modular fashion, comprising four primary components that work in concert:

*   **Backend API**: A Python-based service built with FastAPI that serves as the core of the platform. It manages agent orchestration, LLM integrations (via LiteLLM), thread management, and provides REST endpoints for the frontend and external clients.
*   **Frontend Dashboard**: A web application built with Next.js and React. It provides a user interface for managing agents, interacting with them through a chat interface, configuring workflows, and monitoring their activities.
*   **Agent Runtime Environment**: Secure, isolated Docker containers that provide a complete Linux environment for each agent. This sandbox includes a web browser (Chrome), a file system, and the ability to execute code, enabling agents to perform a wide range of tasks autonomously.
*   **Database & Storage**: Powered by Supabase, this layer handles user authentication, data persistence for agent configurations, conversation histories, file storage, and real-time features for live agent monitoring.

The diagram from the repository's `README.md` visually represents this architecture:

![Architecture Diagram](https://raw.githubusercontent.com/kortix-ai/suna/main/docs/images/diagram.png)

## 2. Folder Structure

The repository is organized into a monorepo structure, with distinct top-level directories for each major component of the platform.

| Path                  | Description                                                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                   | The root directory contains the main `README.md`, `docker-compose.yaml` for orchestration, and setup scripts (`setup.py`, `start.py`).        |
| `/apps/`              | Contains the mobile applications, including a modern React Native app (`/apps/mobile`) for iOS and Android.                                |
| `/backend/`           | Houses the entire Python FastAPI backend, including the core application logic, API endpoints, agent tools, and sandbox management.        |
| `/backend/core/`      | The heart of the backend, containing modules for agent management, API definitions, billing, services, and the agent sandbox implementation. |
| `/backend/core/tools/`| A crucial directory containing the individual Python scripts that define the tools available to the agents (e.g., browser, file system).    |
| `/docs/`              | Contains documentation and architectural diagrams for the project.                                                                       |
| `/frontend/`          | The Next.js frontend application, including all UI components, pages, and logic for the agent management dashboard.                      |
| `/frontend/src/app/`  | The main application directory for the frontend, using the Next.js App Router for routing and page structure.                              |
| `/sdk/`               | A Python SDK that allows developers to interact with the Suna platform programmatically, enabling the creation and management of agents.     |

## 4. Key Components Deep Dive

### Backend

The backend is a modular FastAPI application. The entry point is `backend/api.py`, which initializes the FastAPI app, sets up middleware (CORS, logging), and includes routers from various modules. The core logic is organized into subdirectories within `backend/core`:

*   **`agent_runs.py`, `agent_crud.py`, `agent_service.py`**: These files form the nucleus of agent management, handling the creation, execution, and state management of agents.
*   **`tools/`**: This directory is critical. Each file within it defines a specific capability or "tool" that an agent can use. Examples include `browser_tool.py`, `sb_files_tool.py` (for file system operations), and `web_search_tool.py`. This design makes the system highly extensible, as new tools can be added by simply creating new files in this directory.
*   **`sandbox/`**: Manages the lifecycle of the agent's execution environment.
*   **`services/`**: Contains integrations with external services like Supabase, Redis, and Stripe.
*   **`billing/`**: Handles subscription and credit management.

### Frontend

The frontend is a modern Next.js application that provides a rich user experience for interacting with the Suna platform. Key aspects include:

*   **Routing**: It uses the Next.js App Router, with routes defined by the folder structure inside `frontend/src/app`. For example, `app/(dashboard)/agents` corresponds to the agent management page.
*   **UI Components**: The UI is built using a combination of custom components, Radix UI for accessible primitives, and Tailwind CSS for styling. Reusable components are located in `frontend/src/components`.
*   **State Management**: It uses TanStack Query for server state management (caching, refetching) and Zustand for client-side global state.
*   **API Interaction**: The frontend communicates with the backend via a typesafe API layer, making authenticated requests to the FastAPI endpoints.

### Agent Runtime (Sandbox)

The agent runtime is a key innovation, providing a secure and powerful execution environment for each agent. As described in `backend/core/sandbox/README.md`, it is a Docker container that includes:

*   A full Linux environment with `sudo` access.
*   Google Chrome for browser automation.
*   A VNC server for remote access and debugging.
*   A dedicated workspace and file system.

This sandboxed environment ensures that agent operations are isolated and cannot interfere with the host system or other agents, providing a secure multi-tenant architecture.

### Python SDK

The repository includes a Python SDK located in the `/sdk` directory. This SDK provides a simple, programmatic interface for interacting with the Suna platform. As shown in its `README.md`, it allows developers to:

*   Create and configure agents.
*   Initiate and manage conversation threads.
*   Run agents with specific prompts and stream their responses.

This is particularly useful for integrating Suna agents into other applications, automated workflows, or for testing and development purposes.

### Mobile App

The `apps/mobile` directory contains a React Native application built with Expo. This demonstrates the platform's multi-channel capabilities, providing a native mobile experience for interacting with agents. It shares a similar modern technology stack with the web frontend, using TanStack Query for data fetching and Supabase for authentication, ensuring a consistent experience across platforms.

## 5. Repository Statistics

A brief analysis of the repository's codebase provides insight into its composition:

*   **Total Files**: ~2,227 (excluding dotfiles, `node_modules`, and `__pycache__`)
*   **Python Files**: ~229
*   **TypeScript/JavaScript Files**: ~1,079

These numbers highlight that the project has a substantial frontend codebase (TypeScript/JavaScript) for the user-facing dashboard and mobile app, complemented by a significant and powerful Python backend that drives the core agent logic.

## Conclusion

The Suna repository is a well-architected, comprehensive platform for building and managing AI agents. It employs a modern, modular, and scalable technical stack. The clear separation of concerns between the frontend, backend, and agent runtime, combined with a highly extensible tool-based architecture for agent capabilities, makes it a powerful and flexible open-source project in the AI agent space.
