# OAuth Configuration with Next.js Proxy

**Date Created**: October 29, 2025  
**Purpose**: Document the Next.js proxy architecture that allows OAuth (GitHub, Google) to work while keeping Supabase unexposed to the internet.

---

## 🎯 Architecture Overview

This setup allows you to:
- ✅ Expose only your frontend via Cloudflare Tunnel
- ✅ Keep Supabase private (localhost only)
- ✅ Enable OAuth providers (GitHub, Google) to work correctly
- ✅ Maintain local communication between all services

### **The Problem We Solved**

OAuth providers (GitHub, Google) need to redirect to a **public callback URL** after user authorization. However:
- Our Supabase instance runs on `localhost:8888` (not accessible from internet)
- Exposing Supabase publicly would expose all APIs (auth, storage, database)
- We only want the frontend accessible via `https://kortix.syhc.dev`

### **The Solution: Next.js Rewrites (Proxy)**

Next.js acts as a **reverse proxy** for Supabase API requests:
- Browser requests go to: `https://kortix.syhc.dev/auth/v1/*`
- Next.js proxies (server-side) to: `http://localhost:8888/auth/v1/*`
- Supabase remains unexposed to the internet

## 🔐 OAuth Flow (GitHub/Google)

### **Complete Flow:**

```
1. User visits: https://kortix.syhc.dev/auth
   ↓
2. User clicks "Sign in with GitHub"
   ↓
3. Frontend initiates OAuth:
   - Calls: https://kortix.syhc.dev/auth/v1/authorize?provider=github
   ↓
4. Next.js proxy receives request:
   - Server-side rewrites to: localhost:8888/auth/v1/authorize?provider=github
   ↓
5. Supabase GoTrue processes request:
   - Generates OAuth state token
   - Redirects browser to: https://github.com/login/oauth/authorize?client_id=...
   ↓
6. User authorizes on GitHub:
   - Reviews permissions
   - Clicks "Authorize"
   ↓
7. GitHub redirects back:
   - URL: https://kortix.syhc.dev/auth/v1/callback?code=...&state=...
   ↓
8. Next.js proxy receives callback:
   - Server-side rewrites to: localhost:8888/auth/v1/callback?code=...&state=...
   ↓
9. Supabase GoTrue exchanges code:
   - Validates state token
   - Exchanges auth code for user info
   - Creates session
   - Sets auth cookies
   - Redirects to: SITE_URL (https://kortix.syhc.dev)
   ↓
10. User is logged in! ✅
    - Browser redirected to main app
    - Auth cookies set
    - Session established
```

## ⚙️ Configuration Files

### **1. Frontend: `d:\Homelab\suna\frontend\next.config.ts`**

Add Supabase API proxying via rewrites:

```typescript
import type { NextConfig } from 'next';

const nextConfig = (): NextConfig => ({
  output: (process.env.NEXT_OUTPUT as 'standalone') || undefined,
  
  async rewrites() {
    // Get Supabase URL from environment (localhost for local dev)
    const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL || 'http://localhost:8888';
    
    return [
      // Proxy Supabase auth requests through Next.js
      // This allows OAuth callbacks to work via Cloudflare Tunnel
      // while keeping Supabase unexposed to the internet
      {
        source: '/auth/v1/:path*',
        destination: `${supabaseUrl}/auth/v1/:path*`,
      },
      {
        source: '/rest/v1/:path*',
        destination: `${supabaseUrl}/rest/v1/:path*`,
      },
      {
        source: '/storage/v1/:path*',
        destination: `${supabaseUrl}/storage/v1/:path*`,
      },
      {
        source: '/realtime/v1/:path*',
        destination: `${supabaseUrl}/realtime/v1/:path*`,
      },
      // PostHog analytics proxying
      {
        source: '/ingest/static/:path*',
        destination: 'https://eu-assets.i.posthog.com/static/:path*',
      },
      {
        source: '/ingest/:path*',
        destination: 'https://eu.i.posthog.com/:path*',
      },
      {
        source: '/ingest/flags',
        destination: 'https://eu.i.posthog.com/flags',
      },
    ];
  },
  skipTrailingSlashRedirect: true,
});

export default nextConfig;
```

**Key Points:**
- `source`: URL path that browser requests
- `destination`: Where Next.js proxies the request to (server-side)
- Proxying happens on the server, so localhost URLs work
- Browser never sees the localhost URLs

GOTRUE_EXTERNAL_GOOGLE_ENABLED=true
GOTRUE_EXTERNAL_GOOGLE_CLIENT_ID=REDACTED
GOTRUE_EXTERNAL_GOOGLE_SECRET=REDACTED
# Callback goes through Next.js proxy
GOTRUE_EXTERNAL_GOOGLE_REDIRECT_URI=https://kortix.syhc.dev/auth/v1/callback

GOTRUE_EXTERNAL_GITHUB_CLIENT_ID=REDACTED
GOTRUE_EXTERNAL_GITHUB_SECRET=REDACTED

**Important:**
- OAuth redirect URIs point to your **public domain** (`https://kortix.syhc.dev`)
- Next.js proxy intercepts these and forwards to local Supabase
- `SITE_URL` is where users end up after successful OAuth
- Multiple redirect URLs in `ADDITIONAL_REDIRECT_URLS` for flexibility

## 🔧 GitHub OAuth App Configuration

### **GitHub OAuth App Settings**

When creating your GitHub OAuth App at https://github.com/settings/developers:

```
Application name:              Kortix Staging
Homepage URL:                  https://kortix.syhc.dev
Application description:       Kortix AI Agent Platform - Staging Environment
Authorization callback URL:    https://kortix.syhc.dev/auth/v1/callback
Enable Device Flow:            ❌ (unchecked - not needed for web apps)
```

**Important:**
- GitHub only allows **ONE** callback URL per OAuth app
- Use your public domain (Cloudflare Tunnel URL)
- Next.js will proxy this to localhost Supabase
- For local-only development, create a separate OAuth app with `http://localhost:8888/auth/v1/callback`

### **Multiple OAuth Apps Strategy**

Consider creating separate OAuth apps for different environments:

1. **Local Development**: `http://localhost:8888/auth/v1/callback`
2. **Staging (Tunnel)**: `https://kortix.syhc.dev/auth/v1/callback`
3. **Production**: `https://yourdomain.com/auth/v1/callback`

Store credentials in `.env` and switch based on environment.

## 🐛 Troubleshooting

### **Issue: OAuth Callback Returns 404**

**Symptom:** After authorizing on GitHub/Google, you see a 404 page at `/auth/v1/callback`

**Causes:**
1. Next.js server not running
2. Rewrites not configured in `next.config.ts`
3. Frontend server restarted but not rebuilt

**Solution:**
```powershell
cd D:\Homelab\suna\frontend
# Kill any running Next.js process
npm run dev
```

### **Issue: "Redirect URI Mismatch" Error**

**Symptom:** OAuth provider shows "The redirect URI provided does not match"

**Causes:**
1. GitHub/Google OAuth app callback URL doesn't match
2. `GOTRUE_EXTERNAL_*_REDIRECT_URI` in Supabase doesn't match

**Solution:**
- Ensure GitHub OAuth app has: `https://kortix.syhc.dev/auth/v1/callback`
- Ensure Supabase `.env` has: `GOTRUE_EXTERNAL_GITHUB_REDIRECT_URI=https://kortix.syhc.dev/auth/v1/callback`

### **Issue: OAuth Works Locally but Not via Tunnel**

**Symptom:** OAuth works at `localhost:3000` but fails at `https://kortix.syhc.dev`

**Causes:**
1. `NEXT_PUBLIC_SUPABASE_PUBLIC_URL` not set correctly
2. Cloudflare Tunnel not routing to frontend

**Solution:**
- Set `NEXT_PUBLIC_SUPABASE_PUBLIC_URL=https://kortix.syhc.dev`
- Verify Cloudflare Tunnel routes to `localhost:3000`

### **Issue: Infinite Redirect Loop**

**Symptom:** After OAuth, page keeps redirecting

**Causes:**
1. `SITE_URL` in Supabase doesn't match your app URL
2. Middleware blocking authenticated routes

**Solution:**
- Ensure `SITE_URL=https://kortix.syhc.dev`
- Check `src/middleware.ts` for redirect logic

## 📝 Summary

This proxy architecture allows OAuth to work seamlessly while maintaining security:

1. **Frontend** (`next.config.ts`) proxies Supabase API requests
2. **Browser** requests go to public domain (`https://kortix.syhc.dev`)
3. **Next.js** proxies requests to local Supabase (`localhost:8888`)
4. **Supabase** stays private, never exposed to internet
5. **OAuth providers** redirect to public domain (which Next.js proxies)

All services communicate locally, but OAuth providers see a public callback URL. This is the cleanest, most secure solution for local development with external OAuth. 🎉
